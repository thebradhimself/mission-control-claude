 # ADDENDUM — VISUAL PROGRESS RECORDER                                                                                                                                                                                                                                                     
                                                                                                                                                                                                                                                                                            
  Extend Mission Control with an autonomous screenshot pipeline that captures the app at regular                                                                                                                                                                                            
  intervals, across every meaningful screen and viewport, so I can scrub through visual history and
  see where the product is at any point in time without launching it myself.                                                                                                                                                                                                                
                                                                                                                                                                                                                                                                                            
  This runs in the background via the existing daemon. Treat it as a new automation target under                                                                                                                                                                                            
  Pillar 4 (Situational Awareness) + Pillar 8 (Observability).                                                                                                                                                                                                                              
                                                                                                                                                                                                                                                                                            
  # DELIVERABLES (build in this order — ship each before starting the next)                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                                                            
  ## 1. Capture engine — `mission-control/scripts/screenshot-sweep.ts`                                                                                                                                                                                                                      
  A standalone Node/TS script that:
  - Boots `pnpm dev` if not already running on the expected port (detect via fetch to `/`).                                                                                                                                                                                                 
    If it boots the server, it tears it down on exit. If the server was already up, leave it alone.                                                                                                                                                                                         
  - Uses Playwright (chromium, headless) — add as a devDependency. No other browser engines.                                                                                                                                                                                                
  - Reads route + viewport config from `mission-control/data/screenshot-config.json` (schema below).                                                                                                                                                                                        
  - For each (route × viewport) pair:                                                                                                                                                                                                                                                       
    - Navigate, wait for `networkidle` + a 500ms settle.                                                                                                                                                                                                                                    
    - Hide volatile elements via injected CSS (timestamps, "x seconds ago" badges, animated                                                                                                                                                                                                 
      spinners) — selectors live in the config under `maskSelectors`.                                                                                                                                                                                                                       
    - Capture full-page PNG.                                                                                                                                                                                                                                                                
    - Record load time, status code, console errors, and any failed requests.                                                                                                                                                                                                               
  - Writes to `mission-control/data/progress-snapshots/<ISO-timestamp>/`:                                                                                                                                                                                                                   
    - `<route-slug>__<viewport>.png` for each shot                                                                                                                                                                                                                                          
    - `manifest.json` (schema below)                                                                                                                                                                                                                                                        
  - On any per-shot failure, log it in the manifest with `status: "failed"` and the error — do NOT                                                                                                                                                                                          
    abort the whole sweep.                                                                                                                                                                                                                                                                  
  - Total wall-time budget: 3 minutes. If exceeded, finalize the manifest with what you have and
    exit cleanly.

  ## 6. Retention + disk hygiene                                                                                                                                                                                                                                                            
  Implement `retention` from config on every sweep:

  Log retention decisions to `activity-log.json` as a single summary event per sweep.                                                                                                                                                                                                       
  Hard cap: if `progress-snapshots/` exceeds 2 GB, halt new captures and file a recommendation.
